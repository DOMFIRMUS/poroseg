# Tutorial 4 — Run the full pipeline on your own slices

**Goal:** run the factorial uncertainty analysis on a set of slices of your own, using the synthetic test
dataset of the repository as a template. **Time:** about 2 minutes for the test dataset with `--quick`.
**Data:** `examples/data/` (three synthetic slices with known truth).

## 1. The test dataset

`examples/data/` holds three 640 × 640 px, 16-bit slices of a free-standing cylindrical specimen in air,
generated by `examples/make_example_dataset.py` (which rebuilds them identically):

| File | Content |
|---|---|
| `images/SYN_PACK.tif` | grain packing (the analogue of a granular pack) |
| `images/SYN_BOOL.tif` | Boolean pores in a solid matrix |
| `images/SYN_MULTI.tif` | resolved pores plus sub-resolution micropores |
| `truth/SYN_*_truth.tif` | pixel-grid truth (255 = pore) |
| `samples.csv` | metadata, with the disc ROI given explicitly (`roi_cx`, `roi_cy`, `roi_r`) |
| `lab_porosity.csv` | the true total porosity of each phantom, used as a stand-in for a laboratory value |

`examples/config_example.yaml` is `config.yaml` with the paths pointing to this folder.

## 2. Run the pipeline

```bash
python -m poroseg.run --config examples/config_example.yaml --quick --stages segmentation,descriptive,spatial,sensitivity,perturbation,morphology,inference,report
```

The log ends with the status of every stage:

```
status: {'segmentation': 'ok (5.3s)', 'descriptive': 'ok (38.1s)', 'spatial': 'ok (10.2s)', 'sensitivity': 'ok (9.3s)',
'perturbation': 'ok (10.2s)', 'morphology': 'ok (22.6s)', 'inference': 'ok (9.0s)', 'report': 'ok (0.9s)'}
```

Results are in `examples/data/outputs_quick/` (`--quick` appends `_quick` to the output folder). Start with:

* `RESULTS_DIGEST.md` — the key numbers in words (for example the share of the variability due to the
  analyst's choices, `inference_vd_pp_analyst_pct`);
* `figures/porosity_by_method.png` — porosity of each image by algorithm, with spatial uncertainty bars and the
  reference value;
* `figures/variance_decomposition.png` and `tables/variance_components.csv` — material versus analyst shares;
* `data/segmentation_factorial.csv` — every segmentation of the factorial design;
* `data/spatial_summary.csv` — correlation length, integral range, L_REV and the three uncertainties.

The `legacy` stage audits the original code of the article and does not apply to other data; the `synthetic`
and `ml_baseline` stages do not depend on your images and can be added if you want the benchmark.

## 3. Your own data

1. Copy `examples/data/` to a new folder and replace the images.
2. Edit `samples.csv`, one row per slice: `sample_id`, `label`, `file`, `group`, `holder` (`free` or
   `container`) and `pixel_size_um` are required. Leave `roi_cx`, `roi_cy`, `roi_r` empty to detect the disc
   automatically, or give them (px) to impose it.
3. Edit `lab_porosity.csv` (long format: `sample_id`, `specimen`, `method`, `porosity_pct`). Methods listed in
   `lab.reference_methods` of the configuration are averaged into the reference; a value `uct` is reported but
   never used as the reference. Images without a laboratory value are allowed.
4. Copy `examples/config_example.yaml` next to your data folder and change `paths` (they are relative to the
   configuration file). If your slices are smaller than 500 px, remove `center500` from `roi.designs`.
5. Run the command of step 2 with `--config` pointing to your file, first with `--quick`, then without it for
   the final numbers (10 000 bootstrap replicates).

Check `figures/supp_roi_detection.png` first: if a disc is wrong, give it explicitly in `samples.csv`. The
[user guide](../USER_GUIDE.md) lists every option and output.
